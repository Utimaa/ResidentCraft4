# RE4Craft local transport

Minecraft listens on `127.0.0.1:18044`; the x86 RE4 plugin reconnects as a client. Socket workers own I/O; Minecraft and graphics APIs stay on their game threads. Runtime state, models, texture pixels and input use this connection. Credentials are never read or transmitted.

All fields are little-endian. The packed 16-byte header in `protocol/re4craft_protocol.h` is uint32 magic `0x4234434d` (`MC4B`), uint16 version **6**, uint16 type, uint32 payload size and uint32 sequence. Maximum payload is **32 MiB**. Partial reads accumulate. Both peers must use the same version. Version6 adds a verified native damage-source position and owned-wolf melee; version5 added explicit particle/crumbling/white-overlay render materials. Upgrade the Fabric jar and native ASI together.

## State and input

State80: float64 xyz at offset0; float32 yaw,pitch,health,maxHealth,food,saturation,limbSwing,limbAmount at24; uint32 flags,selectedSlot at56; uint64 player tick at64; uint32 cameraMode,reserved at72. State positions are Minecraft coordinates; body/player angles remain separate from the actual camera. State flags: InWorld1,Screen2,OnGround4,Crouching8,Sprinting16,Swimming32,Dead64. Camera modes: first0,rear-third1,front-third2.

Flags: Enabled1,Focused2,HostAuthority4,Paused8,GuestAuthority16,NativeTraversal32. Authority flags4 and16 are mutually exclusive. NativeTraversal requires HostAuthority and forbids GuestAuthority; Minecraft's exact native window and scripted-event landing handoffs use it. Held bits: Forward1,Back2,Left4,Right8,Jump16,Sneak32,Sprint64,Attack128,Use256. Pressed bits: Inventory1,Drop2,SwapHands4,Camera8,Escape16,Chat32,Command64. Do not duplicate a pressed action as a KeyEvent. GUI mouse bits are left1,right2,middle4. Mouse coordinates map to the actual rendered Minecraft target.

KeyEvent uses SDL scancode1…511, modifiers in the SDL16-bit mask, and Minecraft's SDL action convention: release0,press1,repeat-1. GUI events reach the actual vanilla screen. UTF-8 text uses Minecraft's text handler. Movement bits address the semantic vanilla key mappings, independent of Windows keyboard layout.

The activation anchor records Minecraft and host feet positions at a matching epoch. Conversion is `hostAnchor + minecraftPosition - minecraftAnchor`, with its inverse on inbound host geometry. HostAuthority preserves the legacy displacement-following mode. GuestAuthority enables real Minecraft motion only when complete, fresh terrain coverage contains the player. No raw host coordinate becomes a Minecraft save coordinate.

Focus loss, host pause and the 750-ms input watchdog retain the same session/epoch anchor, player identity and cached collision while releasing controls and holding movement with MotionReady clear. Resuming that epoch uses the original transform, even if inbound native proxy coordinates changed during the hold. Motion continues to publish the anchored held position. A new connection generation or native epoch resets the transform; focus/UI changes never establish a second anchor for the same epoch.

## Guest motion, camera and combat

Motion108: uint32 epoch,flags; uint64 monotonically increasing exported frame; float64 hostFeetXYZ and hostCameraXYZ; float32 velocityXYZ (blocks/tick); float32 yaw,pitch,health,maxHealth,cameraRoll,fov; uint32 cameraMode,reserved. Motion flags: Ready1,OnGround2,Dead4,Screen8,CameraReady16,NativeTraversalAck32. Feet and avatar origin use the same render partial tick. Camera is Minecraft's actual camera, including eye-height smoothing, front/rear mode, host/MC-block clipping, and the inverse of vanilla bob/hurt view transforms. Motion angles describe the actual camera, including front-camera reversal. Angles/FOV are degrees. Ready remains available for a valid death screen; Minecraft owns respawn.

NativeTraversalAck is a fresh receipt of actual interpolated client feet and an applied integrated-server position under the existing anchor. It requires current input, matching generation/epoch/target/player/dimension/server, CameraReady and positive health; Ready, Dead and Screen are forbidden. Actual source feet must reach the target within 0.0625 blocks; native handoff additionally checks the retained landing within 0.125 blocks and a newer exported frame. A receipt cannot grant ordinary guest physics. Invalidated input, pause, death or changed identity removes it; BeamNG rejects the bit. Version 6 layouts are unchanged, but native and Minecraft artifacts must be updated together for this extension.

Enemy72: uint32 id,flags; float64 absolute host XYZ; float32 relative bounds minXYZ,maxXYZ; float32 health,maxHealth,yaw; uint32 kind. ID is positive and stable within the epoch. Flags: Alive1,Dead2,Breakable4,Hostile8. Hostile and Breakable are exclusive. Positive known hostile kinds receive Hostile; ambiguous Ganado/Merchant model kinds13/14/1e additionally require the actual common-Ganado class. Native startup resolves its cEm10 vtable and the distinct Merchant cEm18 vtable through guarded RTTI/hierarchy/executable-method/constructor cross-checks. The marker does not rely on model labels alone. Failure to resolve that optional classification leaves ambiguous kinds out of automatic wolf targeting. Missing/dead/stale actors remove their invisible, unsaved Minecraft LivingEntity proxies. Maximum512 actors. Vanilla reach, attack cooldown, weapon damage, critical hits, sweeps and defense operate on these proxies. Breakable actors identify verified native wooden boxes (kind0x53) and armed native mines/tripwires (kind0x2A, subtypes1/2). Mine unit health is proxy metadata; the original native explosive consumer owns detonation. These accept actual melee/projectile/explosion hits through their original native object damage/destruction handlers; their proxies reject fire/lava damage. Barrels and unverified scripted props are not exported by this extension.

Damage48: uint32 epoch,eventId; float32 amount in **Minecraft health units**; uint32 kind,attackerId,flags; float64 sourceXYZ in absolute host metres. RE4 raw damage is calibrated as `/50`. Epoch/eventId deduplication prevents a second application. Native kind0 is shared-health damage and kind1 is a common enemy attack. HasPosition4 carries the verified attack's actual `from` vector, scaled and checked within128m of the guest; it is mapped with that event's epoch into a positional vanilla MOB_ATTACK DamageSource. One ordinary `hurtServer` call owns shield facing, active-use delay, item blocking, durability, armor and cooldown rules. Missing position remains anonymous, without a guessed nearest attacker. Fatal1 is the verified direct native instant-kill branch and uses vanilla genericKill, independent of shields/armor; Fatal and HasPosition are mutually exclusive. Bit2 remains reserved. Kind0 uses vanilla generic damage. The native projectile/axe identities remain unverified and are not invented.

Loot48 (host message23): uint32 epoch,eventId,source,tier; uint64 sessionId; float64 absolute host XYZ. Sources are Ganado1 and native crate2; tiers are wood0, stone1, iron2, diamond3, netherite4 and enchanted netherite5. Epoch/event/session must be nonzero. Coordinates must be finite and within30 million metres. Session identity remains stable for the native process and event IDs do not reset on reconnect or epoch changes. Minecraft consumes matching-epoch events through its integrated server, spawning actual item entities at the anchored position. Loot event identity is independent of a replaceable enemy snapshot; removing a proxy alone never awards items. Tier5 requires the matching updated native/client pair; protocol6 packet size and all earlier tier meanings remain compatible.

Native current main-campaign subchapter counters0–2 (1-1 through1-3) map to wood,3–5 (chapter2) stone,6–9 (chapter3) iron,10–13 (chapter4) diamond,14–17 (chapter5) netherite and18 (6-1) enchanted netherite. Unsupported character/campaign/chapter states keep native drops. Rewards provide crafting resources rather than equipment. Chapter5 supplies scrap, gold, consumed upgrade templates, diamonds, iron, logs, string, netherrack, real stored-enchantment books and XP bottles; chapter6 increases resource amounts. Minecraft owns crafting, smithing, anvil costs and XP bottle/orb pickup. The 16-late-crate budget supports diamond armor/sword/pickaxe, six consumed netherite upgrades, workstations and seven separate fresh anvil operations, without a Nether world. Saved per-player book rotations are independent for crate and Ganado sources, advance only after every actual ItemEntity spawned and the replay stamp committed, and survive native process restarts. Old gear-milestone metadata remains readable but is inactive. Existing SavedData without optional book_cycles starts each rotation at zero. Loot never writes inventory slots. Accepted native events use a bounded reliable outgoing queue; failed transport enqueue is retried in ascending event order. Minecraft retains at most256 pending events, consumes at most16 per server tick and keeps the FIFO head for up to30 seconds during a matching-epoch focus/coverage hold. Changed epoch, generation, disabled authority, invalid build coordinates, unloaded spawn chunks or a dead player reject the event. One sampled matching-epoch anchor determines its position. SavedData retains unsigned event high-water marks for the64 most recently used native process sessions and bounded non-evicting book rotations for at most64 players; deterministic reward selection and vanilla item entity persistence use the same Minecraft world. There is no durable cross-game transaction acknowledgement or synchronization with a separately reloaded RE4 save.

Melee64: uint32 epoch,targetId,eventId,flags; float32 damage,knockback; float64 attackXYZ; float32 directionXYZ,maxReach. Damage is already the vanilla result; native must not apply critical damage a second time. Flags: Critical1,Projectile2,Fire4,Hazard8,Explosion16,Ally32. Ordinary melee uses the player's eye and vanilla `entityInteractionRange` with a native6-metre maximum. Projectile2 changes attackXYZ to the actual vanilla impact location recorded before the damage callback. Java verifies the projectile's server-side owner UUID matches the bridge player and sends normalized projectile velocity and maxReach1. Native validates player-to-impact distance at most128 metres and impact-to-target-bounds distance at most1 metre. Ally32 is exclusive of other flags and comes only from an actual server-side tamed wolf whose owner is the bridge player, biting a live native hostile proxy. Its actual eye position and target bounds define reach, capped at3m; the origin remains within128m of the guest. Native freshly classifies the current actor, requires Hostile8, rejects crates and checks walls before its normal reaction/one-event damage ledger.

Hazard8 describes actual vanilla contact/burning damage at the proxy, with contact point-to-native bounds distance at most1 metre. Explosion16 describes an actual server explosion center and its blast radius in maxReach, bounded at16 metres (normal TNT uses8). The source must stay within128 metres of the guest player, and native validates source-to-target bounds against that radius. Hazard and Explosion are mutually exclusive and cannot combine Critical or Projectile. Fire4 comes from the actual damage source's fire tag. Minecraft's real damage callback and exposure determine damage; the flags do not invent projectile ownership or grant an arbitrary area hit.

Block bounds use absolute host metres. Up to4096 real nearby vanilla collision boxes are exported, including actual shape bounds for stairs/doors rather than full-cube substitutes. Native actors can collide with these guest blocks.

## Geometry, textures and transparent GUI

Mesh40: uint32 category,frame,batchCount,epoch; float64 hostOriginXYZ. Batches contain uint32 textureId,flags,vertexCount, then vertices of float32 xyz,normalXYZ,uv and uint32 ARGB (36 bytes). At most256 batches and300000 vertices; triangle counts are divisible by3. Category1 independently replaces the real posed avatar; category2 replaces nearby Minecraft blocks/fluids; category3 replaces nearby actual Minecraft entities, particles and breaking overlays. Category3 excludes the local player and invisible host actors, and an empty mesh clears removed effects. All dynamic effects append to one mesh so they cannot replace each other. Vertices are relative to the supplied host origin. Facing and particle billboard rotation are already baked in; native must not rotate them by player yaw again.

Material flags: bit1 is the accepted legacy opaque/double-sided hint; ordinary opaque batches also use0. Translucent2 uses sorted alpha blending. Crumbling4 uses vanilla RGB multiply blending (`DEST_COLOR / SRC_COLOR`), alpha cutoff0.1, repeating destruction-texture UVs, no depth write and a small depth bias. Crumbling is exclusive of Translucent/Particle/WhiteOverlay. Particle8 uses the actual vanilla particle layer, alpha cutoff0.1 and its depth behavior, with Translucent2 when specified by that layer. WhiteOverlay16 reproduces the actual vanilla white overlay texel: RGB uses63/255 of the base and192/255 white, preserving alpha. Unknown bits are rejected. All passes retain native world depth and restore game render state.

Avatar models/poses and all textures come from Minecraft's real renderer. Lossless texture RGBA is preserved up to2048×2048, which fits the32 MiB packet bound. Texture IDs are session-local and textures arrive before referencing geometry. Avatar and HUD target60 Hz. Block/fluid capture discovers loaded nonempty sections at up to10 Hz, rebuilds changed sections incrementally with a2-ms work budget and publishes only changed geometry. Default horizontal/vertical ranges are128 blocks, configurable16…256 through `re4craft.sceneRadius`/`re4craft.sceneHeight`; loaded chunks, section and vertex budgets still apply. Actual entity capture defaults to128 blocks with a64-entity budget; the active, ready integrated-server bridge raises vanilla tracking distance to this range while retaining vanilla chunk/view/broadcast checks. Its mesh origin stays fixed within the epoch. Exact block-state changes invalidate neighboring cached faces; resource-model changes invalidate models. Temporarily unavailable textures retry without replacing valid geometry. Replaceable frame queues discard obsolete frames while texture/melee queues remain reliable.

HUD flags bit0 means bottom-up rows; bit1 selects lossless RGBA32 run/literal encoding. With bit1 clear, the payload after the16-byte prefix is exactly width×height×4 bytes. Encoded packets repeat little-endian uint32 tokens: low31 bits are a nonzero pixel count; high bit set means repeat the following RGBA32 pixel, otherwise copy that count of following RGBA32 literals. Decoding must consume the entire packet and produce exactly width×height pixels within the allocation bound. Raw packets are selected if encoding would be larger. Pixels use Minecraft's premultiplied alpha; native composition uses `ONE / INVSRCALPHA`. Asynchronous GPU readback captures the actual hands, HUD and GUI with world drawing suppressed. Maximum target1920×1080 preserves the host aspect ratio. Minecraft world screenshots are not streamed.

## Terrain and watchdog

Collision32: uint32 epoch,count,flags,reserved; float32 centerXYZ,radius in absolute host metres. Flags: Complete1,Truncated2,SourceIds4. Triangles are three xyz float32 vertices each. Minecraft packets with SourceIds append count records of uint64 sourceKey and uint32 polygonIndex after all triangle coordinates; reserved then carries the registration revision. Other guests retain the original 32+36×count layout. At most200000 finite triangles are decoded into a bounded spatial index. Coverage includes the producer's horizontal radius and vertical capture range. A pre-anchor packet stays cached until the matching anchor exists.

MovingSurfaces24: uint32 epoch,revision,count,reserved; uint64 tick. Each60-byte record contains uint64 sourceKey, uint32 flags and12 float32 entries of a row-major3×4 affine matrix mapping base-world to current-world metres. Flag1 retires a registration. Only matching-epoch/revision registrations from the complete collision snapshot may move. Changed native SAT transforms publish at up to20Hz; an older-than250ms transform cannot carry an entity. Client and integrated server use the same moved triangles for collision/support/camera and carry grounded entities through actual vanilla movement, including rotation. Jumping, stepping off and removal release support.

The producer grants Complete only when every required active entry decoded successfully and the capture was not truncated. In guest mode it can center recovery queries on fresh, matching-epoch Motion feet even when Ready is clear, within the native 32-block transfer bound. The query center, transmitted coverage center and refresh cache agree. Querying those feet does not grant Ready or native movement authority; the returned terrain still has to satisfy normal coverage rules.

Guest movement requires complete, untruncated coverage newer than5 seconds, containing the current/proposed feet with a2-metre margin. Native terrain defaults to a256-metre radius (`TerrainRadius`, clamped32…256), with unchanged200000-triangle/64-MiB read budgets. Its center remains stable until the player moves one quarter of that radius (at least8 metres); active terrain refreshes at least once per second. Missing coverage freezes guest velocity/gravity, releases movement actions and clears MotionReady; a fresh valid frame releases the hold without replacing the epoch's anchor. Minecraft computes walking, strafing, sprinting, crouching, jumping, gravity, friction, fall damage and animation. SkyCraft's MIT triangle collider limits those movements against native slopes, steps, walls and ceilings on both client and integrated server. Actual nearby items, projectiles, ordinary mobs, vehicles and primed TNT also use the collider; invisible host proxies and noPhysics entities retain their own rules. Linked mob AI, TNT fuses and proxy fire timers pause during physics holds. Real server explosions supplement vanilla exposure rays with imported terrain. Ground-navigation mobs retain vanilla A* and movement goals, with actual imported support, body clearance and continuously supported edges supplementing vanilla block nodes; no air-cell floor is invented. Their line of sight also respects imported walls. Owned, standing tamed wolves can select positively identified native hostiles and vanilla Enemy targets, retaining vanilla owner/team/target exclusions and actual melee damage callbacks. Friendly and unverified native kinds are excluded from automatic wolf targeting. Arrows/thrown projectiles refine their vanilla rays against the real native mesh, and marked air-cell host hits invoke normal vanilla hit handlers. The final movement retains real vanilla block collisions. Sneak edge checks consult host ground and Minecraft blocks.

The closest host triangle refines the local player's vanilla selection ray while nearer Minecraft blocks retain their normal hits. Placement/breaking stays in actual vanilla item/use/mining handlers. HostAuthority's legacy support ray provides ground contact without changing normal mining hardness. Ordinary entity positioning avoids recurrent teleport-ack waits. The linked continued-mining gate accepts remote input without taking the desktop mouse.

## Dedicated BeamNG peer

The separate BeamNG adapter listens on `127.0.0.1:18047`. It uses the same version 6 framing and compatible State, Motion, Input, Collision, Enemies and Melee layouts. The vehicle transport retains Type 3 triangle-list and Type 10 indexed geometry compatibility. The new production path sends Types 11–15 for visual pose, material surfaces, compact textures and telemetry. F7 selects BeamNG and F8 selects Minecraft; the inactive peer receives disabled input. Minecraft rejects vehicle-only Types 8–15 and the vehicle hit flag below. No Fabric protocol change is required.

Type 8 TextureChunk retains its 24-byte prefix of uint32 `id,width,height,offset,byteCount,reserved`, followed by exactly `byteCount` original RGBA8 bytes. Reserved is zero. Dimensions are 1–4096 pixels, each image is at most 64 MiB, and each fragment is at most 1 MiB. Production uses at most 64 KiB fragments. Offset starts at zero; continuations must be contiguous with unchanged dimensions. Only a complete image becomes visible. The vehicle transport bounds actual incomplete and queued CPU storage together at 384 MiB, with at most 8 partial images and 256 texture IDs. Completed production vehicle maps may be stored losslessly compressed internally; wire pixels and validation are unchanged. The complete active catalog has a separate 512 MiB decoded-size bound, while renderer-retained CPU storage is capped at 384 MiB. One original image of at most 64 MiB is reconstructed only for GPU upload or device Reset; warm draws do not decompress it. These bounds do not describe total process or GPU memory. Disconnect clears partial images. Minecraft's 2048-pixel dimensions and 64 MiB allocation limits remain unchanged.

Type 9 VehicleInfo is 24 bytes: uint32 `epoch,vehicleId,nodeCount,flags`; float32 `collisionRadius`; uint32 `reserved`. Epoch and vehicle ID must be nonzero, node count is 1–20,000, radius must be finite and greater than zero but at most 128 metres, and reserved is zero. Flag 1 reports construction of matching complete native terrain and successful vehicle-side collision ray witnesses; other flags are rejected. This flag describes a readiness gate, not evidence that an NPC contact test passed. Node count and radius measure the actual cluster attached to the native reference node, using BeamNG's current cluster queries. Readiness still requires attached extent at most 8 metres. Separately, the producer measures every live node, including detached debris, and requires finite all-node extent at most 128 metres fully contained in the fresh imported terrain with a 0.5-metre margin. Detached nodes retain real simulation/collision/rendering but cannot attribute chassis-speed Hit64 events. Missing cluster information fails closed; no guessed vehicle dimensions or ignored unsupported debris grant authority. Missing or stale coverage, focus loss and invalid motion release controls and hold the owned BeamNG staging simulation.

Type 10 VehicleMeshChunk has a 24-byte prefix of uint32 `epoch,frame,totalBytes,offset,byteCount,reserved`, followed by exactly `byteCount` body bytes. Epoch is nonzero and reserved is zero. A fragment is 1–65,536 bytes. Its offset and byte count must fit within `totalBytes`; continuations must match the pending epoch, frame and total length and start exactly after the previous fragment. The payload remains within the common 32 MiB packet limit.

The complete body begins with the existing 40-byte Mesh header: uint32 `category,frame,batchCount,epoch`, then float64 `hostOriginXYZ`. Category must be 1; epoch and frame must equal the chunk prefix. Each batch has a 16-byte prefix of uint32 `textureId,flags,vertexCount,indexCount`, followed by `vertexCount` original 36-byte Vertex records and `indexCount` little-endian uint32 triangle indices. Vertex layout, material flags and texture identities are unchanged. Each index must be smaller than its batch's vertex count. Counts are nonzero, vertex count cannot exceed index count, index count is divisible by three, and the sum of indices across all batches is at most 300,000. At most 256 batches are accepted. These constraints bound the complete indexed body at 12,004,136 bytes, within the general 32 MiB bound. Unknown material bits, invalid attributes, extra tails and inconsistent chunk/body identities are rejected.

The transport publishes nothing until the complete body and all indices have been validated. It expands each index to an exact copy of the corresponding source Vertex bytes, retaining triangle order and per-batch materials. One pending assembly is retained. An offset-zero fragment with a strictly newer epoch/frame can replace an incomplete frame; replayed or older keys are rejected. Newness uses unsigned 32-bit serial differences smaller than `0x80000000`, including wraparound. Disconnect clears partial data. The producer finishes a started frame before selecting the newest unsent frame, except when mode changes or repair cancel remaining geometry. Small framed packets can still finish normally before a new assembly begins.

Type 11 VehiclePose is 112 bytes: uint32 `epoch,vehicleId`; uint64 `tick`; float64 `sourceSeconds`; float64 `hostXYZ`; float32 `carQuaternionXYZW`; float64 `cameraXYZ`; float32 `cameraQuaternionXYZW,fov`; uint32 `cameraMode`. Quaternions are normalized in the host Y-up frame. Modes are cockpit 0, orbit 1 and chase 2. Identity, time, positions, quaternions and FOV are validated. Car and camera come from the same actual game-engine visual snapshot, read immediately before publication. Motion retains the separately validated vehicle-VM physics snapshot and all gameplay/readiness authority; the two packets share identity, epoch and publication tick but can have different body positions. A validated vehicle-VM visual fallback retains its genuine capture time and cannot rewind a newer visual sample.

The visual renderer buffers actual source-body samples by 35–50 ms, adapting within that range to measured delivery variation. It interpolates positions and unit quaternions without predicting future physics. Repeated source timestamps do not advance body history. A smoothly bounded 0.85–1.35 playback rate recovers timing debt after a short starvation instead of carrying that delay for seconds. Camera offsets and orientations retain their own high-resolution arrival timeline with a separate 20 ms buffer. The native camera hook retains an immutable presentation pose only after both camera writes succeed; the renderer uses the pose matching the camera tuple actually applied to the native world. History resets on vehicle/epoch changes, camera switches, arrival gaps above 150 ms or displacements above 8 metres. Samples expire after 250 ms. Stale, repaired or teleported vehicles cannot interpolate across an old pose history.

A genuine fresh source camera may retain CameraReady16 while a physics hold clears Ready1. Native visual continuation is limited to two seconds and requires a previously fully ready, successfully drawn car, matching vehicle/epoch and fresh source pose, camera, state and deformation. Native movement/fire remain filtered. Physics movement and contacts still require the complete original readiness checks. Disconnect, focus loss, native menu/death/cutscene, stale samples or an epoch/vehicle change end the continuation; an initial unready import cannot use it to bootstrap.

Type 12 VehicleMaterial has a 120-byte prefix: uint32 `epoch,id,layerCount,flags`; float32 `alphaRef`; uint32 `reserved`; three float32 RGBA paint colors; three float32 paint-data vectors ordered `roughness,metallic,clearcoat,clearcoatRoughness`. Colors are actual linear vehicle values. Epoch is nonzero, material ID is 1–256, layer count is 1–4, alpha reference is normalized 0–1, and reserved is zero. Flags are DoubleSided 1, Translucent 2, AlphaTest 4, TranslucentZWrite 8 and BlackSkyCubemap 16, plus the blend operation in bits 8–10: None 0, LerpAlpha 1, AddAlpha 2, Add 3, Mul 4, PreMulAlpha 5. The permitted flag mask is `0x71F`; other bits are rejected. Depth writing comes only from the actual `translucentZWrite` field. Blend None does not infer that property. Flag 16 comes only from the actual `cubemap == BlackSkyCubemap` preset, whose installed six faces all reference the verified black image. It removes specular/clearcoat environment reflection while retaining ambient diffuse illumination. `translucent=true` with blend None retains its exact blend operation.

Each 128-byte layer contains 11 uint32 texture references in this order: base color, palette, opacity, metallic, roughness, normal, ambient occlusion, clearcoat, clearcoat roughness, emissive, detail normal. Zero means no map. These are followed by uint32 layer flags; float32 `baseRGBA,emissiveRGB,emissiveNits`; ten float32 values `opacity,metallic,roughness,AO,clearcoat,clearcoatRoughness,normalStrength,detailNormalStrength,detailScaleX,detailScaleY`; and uint32 `mapUV1Mask,reserved`. Layer flags are InstanceDiffuse 1, InstanceOpacity 2, PaletteBaseColor 4, PaletteRoughness 8, PaletteMetallic 16, PaletteClearcoat 32 and PaletteClearcoatRoughness 64. Each of the 11 UV-mask bits selects the second source UV set for its map. References are at most 65,535; reserved is zero. Numeric values and exact payload length are checked; the maximum material payload is 632 bytes.

The renderer follows the source layer composition: opacity factor multiplies the opacity map's red channel; layer zero replaces the initial values; later layers blend by their resulting opacity. Scalar material factors multiply their maps and weighted paint data. Base-map alpha does not become v1.5 material opacity. PreMulAlpha premultiplies the base color before diffuse/specular decomposition, retains the source opacity in output alpha, and permits reflection independently of alpha. Paint weights preserve the original palette and its source UV set. Lit HDR RGB passes through the installed default ACES fitted display transform before SDR gamma encoding; output opacity is unchanged. Automatic BeamNG exposure is not exported. Lighting and sky/ground reflection remain D3D9 approximations of BeamNG's full rendering pipeline. The display correction passed numeric/compiler checks and hardware replay of the complete actual Covet; its live RE4 appearance still requires observation.

Type 13 VehicleSurfaceChunk uses the Type 10 24-byte fragment prefix and the same sequential, complete-frame and newer-key replacement rules. Its body starts with Mesh40, then a 24-byte capture record: float64 `sourceSeconds` and float32 `carQuaternionXYZW`. The capture is the actual reference state copied immediately before the GPU readback request. It is not the later publication pose or a claimed internal GPU timestamp.

Each surface batch has 20 bytes of uint32 `textureId,flags,vertexCount,indexCount,materialId`, followed by 44-byte vertices and uint32 indices. Vertex44 is ten float32 values `x,y,z,nx,ny,nz,u,v,u2,v2`, then uint32 ARGB color. Referenced actual GPU UV channels are preserved within the finite ±1,000,000 contract. Undefined secondary slots are zeroed only when the material has no actual map sampling them; a missing or invalid referenced UV set fails export. An unused map's UV selector alone does not require that buffer. The new path uses white vertex color because source factors live in Material12. Existing Vertex36 and Minecraft batches remain unchanged.
